# 震動衝擊測試報告自動化｜第二版

伺服器震動與衝擊測試報告（Excel）的製作工具。從實驗室現場拍照歸位，到產生**公司格式**（Shock & Vibration Engineering Report）的 Excel 報告。

第二版重點（2026-11-17）：依過往正式報告，Excel 輸出改成公司格式。

線上使用：<https://jabil-structure.github.io/Auto-test-report/>（照片與資料只存在各自的瀏覽器，不會上傳）。

## 怎麼開始用

1. 打開 `dist/autoreport.html`（Chrome、Edge 或 Safari）。只有這一個檔案，不用安裝，也不用網路。
2. 按「載入示範資料」，會建立一個示範測試案（照片都是程式畫的假圖，沒有任何真實產品照片）。
3. 依上方分頁 ①～⑦ 走一遍，最後在「⑦ 產生報告」按「產生 Excel 報告」。
4. 第一次使用時，在「⑦ 產生報告」最下方上傳公司標誌、確認頁尾文字（存在這台裝置，之後所有測試案共用）。

## 產生的 Excel 報告

工作表順序與過往報告相同：

| 工作表 | 內容 |
|---|---|
| Cover | 標誌、報告標題、`{Project} @ {Phase}`、測項清單 |
| Summary | 各測項的 Sequence、Progress、Status（Pass／Defect／Fail）、日期，Overall Progress 公式 |
| 每個測項一頁 | 1. Purposes、2. Specification（Profile 表）、3. Lab & Equipment、4. Configurations（配置表、扭力表、4.3 測試前照片）、5. Results Summary（逐分項判定表）、6. Testing Setup（架設照＋輸入波形）、7. Accelerometer Setup（紅色橢圓＋箭頭特寫＋響應圖）、8. Testing Detail Results（8.1 檢查表、8.3 測試後照片） |
| Issue Lists | 問題清單，`#01` 連到問題頁 |
| #01、#02… | 每個問題一頁：SKU、零件、測項、面／軸、描述、照片、Root Cause、對策、驗證結果 |

報告內容是英文；系統介面是中文。數值（G 值、PSD、時間）預設是 `[ ]`，請依本次規範填寫。
系統沒有收集的資料（8.2 卡片位移量測等）會留 N/A，產生後直接在 Excel 補上。

## 資料存在哪裡（資安）

- 照片和資料**只存在這台裝置的瀏覽器裡**（IndexedDB），不會上傳到任何伺服器，也不會送到任何 AI 或外部服務。
- 換電腦、換瀏覽器或清除瀏覽器資料，就看不到原本的資料。重要資料請用「匯出專案檔（.zip）」備份到公司 OneDrive。
- 匯出的 zip 裡，照片已依「拍照節點／清單項目」自動命名、分好資料夾（架設照放在「架設照」資料夾），解壓縮後可以直接放 OneDrive 存檔。

## 流程對照

| 分頁 | 做什麼 | 對應報告 |
|---|---|---|
| ① 基本資料與測項 | 填基本資料（英文）；選測項（自動展開分項：震動 X/Y/Z 三軸、衝擊六面）；報告大項；每個測項的報告文字與表格（預設帶入，可刪改）；4.1 配置表、4.2 扭力表（可從 Excel 直接貼上）；8.1 檢查項目；拍照清單，可存成機種清單下次沿用 | Cover、各測項頁 1～4、8.1 |
| ② 時間軸與拍照 | 分項依實際順序排成時間軸；在任何分項後面加一組拍照節點；照清單逐格拍照；每個分項拍「架設照」 | 4.3、8.3、6.1 |
| ③ 框選裁切 | 母圖上畫框，每個框是一個零件特寫；勾「加速規」的框會畫紅色橢圓與箭頭 | 4.3、8.3、7.1 |
| ④ 照片回顧 | 依時間軸比對同一角度或零件，找出問題是哪個階段產生的 | － |
| ⑤ 問題與判定 | 逐分項判定（Pass／Defect／Fail／依風險跳過）、功能檢查與備註；問題紀錄（英文）可指定對應的 8.1 檢查項目 | 5.1、8.1、Issue Lists、#01… |
| ⑥ 響應圖 | 上傳實驗室的響應 Word 檔，抽出圖片後指定到分項（6.1 輸入波形）或加速規（7.1 響應） | 6.1、7.1 |
| ⑦ 產生報告 | 確認每個報告大項的測試前／後節點、勾選要放的照片、報告設定（標誌、頁尾），產生 Excel | 全部 |

## 從第一版升級

第一版的測試案打開時會自動升級：

- 基本資料欄位對應到新欄位（產品→Project Name、機種→Code Name、階段→Phase、樣品編號→Testing SKU）。
- **軸向改成公司慣例**（X＝前後、Y＝左右、Z＝上下）。第一版的 X 是左右、Y 是前後，升級時依實際方向（左右／前後）重新對應，照片與判定不會錯位。
- 中文測項名稱換成測項庫的英文名稱（原名稱保留在資料裡）。
- 判定多了 Defect；問題紀錄多了 Status、Defect Number、Root Cause 等欄位。

## 還沒做的（之後的版本）

- **多人同時編輯**：目前每台裝置各自一份，多人可各自拍再用「匯入／合併專案檔」合併。正式版要改存公司 OneDrive／SharePoint（需 IT 確認 Microsoft Graph 或 Power Apps 權限）。
- **一份報告多個配置**：過往報告的 Summary 可並列 2 組配置、測項頁加 -1、-2。目前一個測試案＝一個配置。
- **手機現場使用**：單一 HTML 檔在 iPhone 上無法直接從檔案開啟，需要放到公司內部網頁主機或 SharePoint 網站上（要先和 IT 確認架設位置）。
- **輔助功能**：自動辨識零件、自動比對防鬆標記等。若用外部 AI 服務，必須是使用者明確啟用的選用功能，且須先經公司同意。
- iPhone 預設的 HEIC 照片格式部分瀏覽器無法顯示，建議相機設定改成「最相容」（JPEG）。

## 程式結構（給接手開發者／Kiro）

純前端，原生 JavaScript，沒有框架、沒有建置相依（只需要 Python 3 來合併檔案）。

```
src/
  index.html             外殼
  styles.css             樣式
  js/
    00-util.js           共用小工具（建立 DOM、彈窗、選檔、下載）
    10-defaults.js       預設資料：測項庫（英文報告文字）、軸向、10 個母圖角度、零件清單、8.1 檢查項目、基本資料欄位
    20-store.js          儲存層（IndexedDB）。介面已抽象化，可換成 OneDrive 版
    30-model.js          資料結構與業務規則：時間軸、拍照節點、建議前後照片、提醒、判定、舊版升級、合併
    40-imaging.js        裁切、縮圖、加速規紅色橢圓箭頭合成圖（不快取解碼結果，避免大量照片時記憶體不足）
    50-docx.js           從 Word 檔抽圖片
    60-report-layout.js  Excel 輸出（公司格式；改版面只改這個檔）
    65-package.js        專案檔 zip 匯出／匯入合併
    70-demo.js           示範假資料
    80~87-ui-*.js        各分頁畫面
    99-app.js            分頁切換與啟動
vendor/                  ExcelJS 4.4.0、JSZip 3.10.1（MIT 授權）
build.py                 合併成 dist/autoreport.html
```

修改後重新產生單一檔案：

```
python build.py
```

資料結構的完整說明寫在 `src/js/30-model.js` 開頭的註解。重點：

- 原始照片永遠不修改；裁切框存成相對座標（0～1），輸出時才裁切。
- 裁切框定義在「角度」上（母框），個別照片的微調存在 `regionOverrides`。
- 拍照節點掛在「某個分項之後」，所以調整時間軸順序時，節點會跟著分項移動。
- 架設照（報告 6.1）不屬於拍照節點：`nodeId=null, itemId='setup', subitemId`。
- 報告大項的測試前／後節點：沒手動指定時，由 `suggestAssignment` 依時間軸自動建議。
- 舊資料一律經過 `AR.model.migrate()`（開啟、匯入、合併、產生報告前），可重複呼叫。
